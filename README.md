# cc-rework-route

不合格品与返工过程管理服务：不合格记录开立、处置决定拆分（返工 / 报废 / 让步接收）、
返工工序、复验、并回库存，以及数量去向与批次谱系查询的完整闭环。

## 开发环境

- JDK 21
- Maven Wrapper 3.9.9
- Spring Boot 4.1.1
- H2（内存库）+ Spring Data JPA（悲观行锁 + 乐观版本号）

迁移项目沿用现有 Spring Boot 版本，其他项目使用上述版本。

## 常用命令

运行测试：

    ./mvnw clean test

启动服务：

    ./mvnw spring-boot:run

## 主要业务规则

### 1. 不合格记录关联批次与受影响数量

- 每条不合格记录（NC）必须关联一个生产批次，并单独记录 `affectedQuantity`。
- 开立时在**批次行锁**内把受影响数量从可用库存冻结（写 `BLOCK` 库存移动），
  可用库存不足直接拒绝，不产生任何记录。

### 2. 处置决定三分法

- 处置把受影响数量拆分为 `reworkQty`（返工）、`scrapQty`（报废）、
  `concessionQty`（让步接收）三部分。
- 三部分均为非负数，且**之和必须严格等于原受影响数量**，否则整个请求拒绝（HTTP 400）。
- 返工数量大于 0 时必须同时给出返工指定工序的有序列表。

### 3. 确认处置的原子性

- 确认在单个数据库事务内完成：数量校验 → NC 状态校验 → 原子生成返工子批次、
  报废记录、三类库存移动、让步数量回补可用库存、NC 置为 DISPOSED。
- 任一数量或状态校验失败整体回滚，**不会留下子批次、报废记录或部分库存变动**。

### 4. 原始数量不可重复消费

- 同一 NC 只能有一个已确认处置。确认按“批次行锁 → 不合格记录行锁”固定顺序加锁，
  两个处置并发提交时，后到者一定看到 `DISPOSED` 状态并被拒绝（HTTP 409），
  同一原始数量不会被消费两次，库存不会重复扣减/释放。

### 5. 返工工序、复验与放行的顺序

返工子批次的状态机：`CREATED → IN_PROGRESS → COMPLETED → MERGED`。

- 必须按处置指定的工序**顺序**完成：跳序、重复、未知工序均拒绝（409）。
- 全部指定工序完成（COMPLETED）后才允许提交复验，提前提交拒绝。
- 复验结果带**单调递增版本号**；放行并回时：
  - 必须存在复验结果；
  - **最新版本**结论必须是 PASS（最新为 FAIL 不得放行）；
  - 请求携带的 `expectedVersion` 若不等于最新版本则拒绝——**旧版本结果（即使旧版合格）
    也不得放行**。
- 并回在“批次行锁 → 子批次行锁”内完成，状态置为 MERGED 并把数量加回可用库存；
  重复并回拒绝，数量不会翻倍。
- 所有推进在子批次行锁内串行，因此并发完成工序与提交复验也不会破坏上述顺序。

### 6. 处置业务号幂等与不可变

- `businessNo` 为全局唯一幂等键：
  - **相同内容重放**（NC、三个数量、工序列表全部一致）返回原处置结果，
    响应中 `replayed=true`，不重复生成任何记录、不重复释放库存；
  - **同业务号内容不同**返回冲突（HTTP 409），不做覆盖。
  - 并发同业务号请求由唯一约束 + 锁后复查保证收敛到同一份处置。
- 处置一旦 CONFIRMED 即冻结，不能修改任何数量/工序；
  只能通过“纠正记录”接口**追加**纠正措施，原处置与追加记录共同保留完整谱系。

### 7. 数量去向、进度、复验与谱系查询

- `GET /api/nonconformances/{ncNo}/quantity-trace`：受影响数量的返工（在途/已并回）、
  报废、让步接收数量及全部库存移动台账。
- `GET /api/rework/{subBatchNo}/progress`：指定工序、已完成工序与子批次状态。
- `GET /api/rework/{subBatchNo}/reinspections`：全部复验版本与最新结论。
- `GET /api/batches/{batchNo}/genealogy`：批次 → 不合格 → 处置（拆分数量）→
  返工子批次（工序/复验/并回）与报废记录 → 纠正记录的完整谱系。

库存守恒恒等式：`期初数量 = 当前可用 + 在途返工 + 已报废`
（让步接收与复验合格并回的数量都回到可用库存）。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/batches` | 登记生产批次 |
| POST | `/api/nonconformances` | 开立不合格记录（冻结受影响数量） |
| POST | `/api/dispositions` | 提交并确认处置（幂等） |
| POST | `/api/dispositions/{businessNo}/corrections` | 对已确认处置追加纠正记录 |
| POST | `/api/rework/operations/complete` | 按序完成一道返工工序 |
| POST | `/api/rework/reinspections` | 提交复验结果（自动分配版本号） |
| POST | `/api/rework/merge-back` | 复验合格并回可用库存（可带 expectedVersion 防旧结果放行） |
| GET | `/api/nonconformances/{ncNo}/quantity-trace` | 不合格数量去向 |
| GET | `/api/rework/{subBatchNo}/progress` | 返工进度 |
| GET | `/api/rework/{subBatchNo}/reinspections` | 复验结果历史 |
| GET | `/api/batches/{batchNo}/genealogy` | 批次完整谱系 |

错误码：参数/数量非法 `400`；状态冲突、重复消费、顺序错误、旧版本放行、同业务号不同内容
`409`；资源不存在 `404`。

## 测试

`src/test/java` 下覆盖：

- 拆分数量校验与失败回滚不留部分结果；
- 同一数量并发双处置只能成功一次（`ConcurrencyTest`）；
- 同业务号并发重放收敛为一份处置、让步数量只释放一次；
- 并发完成同一工序只生效一次；工序完成与复验并发时复验不可能先于工序落地；
- 并回并发只加回一次；
- 旧复验版本不放行、FAIL 不放行、未完成工序不放行；
- 业务号幂等/冲突、已确认处置只能追加纠正记录；
- 数量去向、返工进度、复验历史、批次谱系查询；
- 完整闭环的 MockMvc HTTP 测试。
